# 1) DB migration — quote templates + status audit
Create apps/app/migrations/009_quote_templates.sql:
------------------------------------------------
BEGIN;

CREATE TABLE IF NOT EXISTS quote_templates (
  id TEXT PRIMARY KEY,
  tenant_id TEXT NOT NULL REFERENCES tenants(id),
  name TEXT NOT NULL,
  description TEXT,
  body_html TEXT NOT NULL,        -- HTML with {{variables}} placeholders
  items_json JSONB,               -- optional default line items [{label, qty, unit, price}]
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Optional: track status transitions
CREATE TABLE IF NOT EXISTS quote_events (
  id TEXT PRIMARY KEY,
  quote_id TEXT NOT NULL REFERENCES quotes(id),
  event TEXT NOT NULL,            -- 'created'|'sent'|'accepted'|'rejected'
  meta JSONB,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

COMMIT;
------------------------------------------------

# 2) Server — Quote endpoints (protected)
Add to apps/app/server/index.ts under /api/app/* (ensure ensureAuth + tenant scoping):
- POST /api/app/quotes
  Body: { customerId, items:[{label,qty,unitPrice}], templateId?, variables?:object, notes? }
  Steps:
    • If templateId provided, load template, merge items/variables into HTML.
    • Compute subtotal/tax/total (simple 0% tax placeholder; leave hook).
    • Insert into quotes (status='draft'), add quote_events 'created'.
    • Return {id}.

- POST /api/app/quotes/:id/send
  Body: { subject?, message? }
  Steps:
    • Generate a secure view token (crypto.randomBytes(24).toString('hex')); store hashed if you prefer.
    • Email customer via sendMail with a link /q/:id?t=<token>.
    • Update quotes.status='sent'; quote_events 'sent'.
    • Return {ok:true, link}.

- GET /q/:id (public)
  Query: t=<token>
  Steps:
    • Validate token for this quote (allow simple token column on quotes or a separate quote_tokens table—choose simplest).
    • Return sanitized quote HTML + line items + Accept/Reject POST endpoints.

- POST /api/quotes/:id/accept (public)
  Body: { token, name, email }
  Steps:
    • Validate token; set quotes.status='accepted'; quote_events 'accepted'.
    • (Side-effect) Create a draft contract from default contract template (if exists)—store relation on contracts.quote_id.
    • Email both baker & customer confirmation.

- POST /api/quotes/:id/reject (public)
  Body: { token, reason? }
  Steps:
    • Validate token; quotes.status='rejected'; quote_events 'rejected'; email baker.

Implementation notes:
- Persist line items JSON on quotes.items_json if your schema supports; else create a small quote_items table.
- Keep tenant_id on every insert.
