status text check('pending'|'confirmed'|'canceled'), notes text,
created_at timestamptz default now()

2) Server — Booking API (auth + public)

In apps/app/server/routes.ts (tenant-scoped, behind authGuard unless stated):

Admin (auth)

GET /api/booking/settings → load by tenant_id (create defaults if none).

POST /api/booking/settings → upsert settings (validate services array).

GET /api/booking/list?status=pending|confirmed|canceled → list tenant bookings.

POST /api/booking/confirm/:id → set status confirmed.

POST /api/booking/cancel/:id → set status canceled.

Public

GET /api/booking/availability?serviceId=&from=YYYY-MM-DD&to=YYYY-MM-DD

Compute slots from booking_settings (workdays + slot_minutes + lead_time_days),
remove conflicts using existing bookings with status != 'canceled'.

Return an array of ISO datetimes.

POST /api/booking/create

Body: { tenantSlug|subdomain?, customer_name, customer_email, serviceId, start_at, notes? }

Resolve tenant from slug/subdomain or current host; validate slot is still free; insert pending booking; return { ok:true, bookingId }.

Keep it simple: no email/webhooks yet. Both endpoints must respect BOOKING_ENABLED.
